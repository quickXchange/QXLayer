name: Native Publish planner loss
description: Native policy/schema loss boundary and the distinction between project Drizzle changes and the platform planner.
---

Do not claim a project-only Drizzle update, corrected offline SQL or exported
namespace has repaired the native Replit Publish plan. Compare a fresh native
preview with actual Development catalog expressions and private namespaces.

**Why:** Correct catalog policies and an existing visible private Auth namespace
were lost in native planning. The same predicate loss is reproducible in
Drizzle's push-policy squashing, which omits using/withCheck, while its ordinary
migration serializer preserves them. Public-only filtering independently omits
private tables. The deployed native service's internal version/configuration is
not exposed, so the upstream reproduction is not proof of its internal stack.

**How to apply:** Treat native generation as a separate verification boundary.
Require per-policy expression/role/command comparisons and private schema,
constraint and FORCE RLS coverage. If the native output remains lossy, retain
the publishing hold and request a platform-supported preview correction; never
patch node_modules or move private storage into public as a claimed native fix.
