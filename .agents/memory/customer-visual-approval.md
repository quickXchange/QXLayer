---
name: Customer website visual approval
description: The customer-facing design must be approved before any new backend phase begins.
---
Wait for the user's explicit visual approval of the shared customer website before starting any new backend phase. Visual approval alone does not request or authorize that next phase.

The customer website must look significantly premium and visually impressive, with the exchange widget as the main centerpiece. Prioritize the actual first mobile viewport, a larger/cleaner/dominant widget, layered depth, visible elegant animated atmosphere and illuminated cards. Keep it professional, fast and trustworthy, with smooth/lightweight motion and multi-tenant branding preserved.

**Why:** The user repeatedly rejected incremental polish/lighting passes as still too simple. They require a clear first-opening “wow” effect and a much stronger crypto/fintech identity, especially on mobile.

**How to apply:** Check the actual first mobile viewport and composition, not only desktop glow strength. Treat backend architecture, entitlements, plans, isolation, admin applications and non-executing sandbox behavior as fixed during visual iterations. Honest sandbox notices remain necessary, but the financial engine being deferred is not a reason to use a development-template visual design.
