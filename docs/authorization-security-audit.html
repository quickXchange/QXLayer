  • After final dependency updates and workflow restarts, all 61 protected route/method combinations returned 401 anonymously. Requests were valid JSON where applicable; no validation error was counted as authorization success.

Access model reviewed

Clerk supplies the authenticated identity; active role and tenant memberships are resolved from the database. Client tenant IDs select a context only after membership validation. Writes also enforce staff grants. Customer records are filtered by authenticated customer_user_id; attachments by owner_user_id, with explicit submitted-file Super Admin access. Child history/file queries use parent IDs obtained only after the parent ownership check. Tenant-owned queries use the authorized tenant ID. Read-only operations run in read-only transactions. No RLS was reintroduced.

Public endpoints intentionally expose restricted catalogs, active branded sites and sandbox configuration. Public simulated Exchange orders are capability-protected: signed quotes bind tenant/settings/currency/expiry and tracking tokens bind tenant and order. A UUID alone does not grant access. Keys/webhooks/payments remain sandbox configuration, not live financial execution.

Security changes and remaining risks

Applied brace-expansion 5.0.9 → 5.0.12 and fast-uri 3.1.7 → 3.1.8 as narrow dependency overrides. The scanner changed from 4 high + 2 moderate findings to 2 high + 0 moderate. Added repeatable development-only authorization fixtures and pnpm verify:authorization. No visual changes, new database policies, production changes or migrations.

Scope and limitations

This verifies the development code and development database, and builds production artifacts. It does not inspect deployed credentials/data or make guarantees about deployment configuration. Live cryptocurrency, wallet, blockchain, payment and webhook execution remain excluded. Unsupported CRUD routes are not exposed APIs. Signed-in HTTP checks did not exercise permitted administrator creation or external DNS verification; those permission, assignment and mocked DNS cases are covered by isolated foundation/customer/service regressions instead.
